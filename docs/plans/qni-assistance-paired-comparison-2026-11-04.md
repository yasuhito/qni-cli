# qni-cli の道具利用を比較する対比較案

状態は計画のみ。モデル呼び出し、新しい実行器、試験測定は追加していない。以下の設定は推奨案であり、採用・承認済みの条件ではない。

## 現行21条件はすでに道具なし

`fbd0e29e98f32a2230b90e70c92db3592e91a762` の測定では、モデルは qni-cli を実行できなかった。

- `src/research_solver.ts` は課題ごとの空の作業場所で Pi を起動し、`--no-tools`、`--no-context-files`、`--no-skills`、`--no-session` を指定した。Bridge も組み込み道具を `tools: []` にし、設定読み込み元を空にした。
- 全1,325件・113,304行の実ログで、道具実行イベントと `toolCall` / `tool_use` / `tool_result` は0件だった。
- 全件の system の `sections.preamble` は固定した保存済みプロンプトと一致した。課題用プロンプトにはゲート一覧、中立 JSON の契約、課題本文があり、`qni` という語はなかった。検証条件や標準解は与えていない。作業場所は `sections.cwd` に記録されている。生ログの system の `content` は空なので、それを通信先へ送った system 本文そのものと取り違えない。
- qni-cli は課題の準備、回答保存、内部形式への変換、非公開の事後採点に使った。モデルが回路を実行・表示・検算する手段ではなかった。

ただし、実行時の文脈がまったくない試験ではない。とくに Bridge には Claude Code のプリセットと OAuth アカウント由来の文脈がある。この実行条件は承認済みだった。Pi のログだけが SDK 内部の全プロンプトを記録しているとは扱わない。

したがって、現行の図から「qni-cli を使うとモデルがよく解ける」とは結論できない。新しい道具付き実行と古い図をそのまま比較しても、採点器や時間上限などが異なるため、対比較にはならない。

## 今回固定できた採点条件

逆三角関数を含む数値の角度式と旧保存表記の互換性は、ソース HEAD `4230ba25a4500abca9655f08e07481860104b159` で修正した。[修正済み採点器で原回答1,323件を再診断した結果](../reports/model-effort-legacy-angle-repair-2026-11-05.md)は1,222合格・93不合格・8不許可・エラー0である。これは同じ回答に対するソフトウェア・文法の差であり、道具を使う効果の測定ではない。旧行列は不変である。

数値 API と中立 JSON では `sqrt`、`asin`、`acos`、`atan` と必要な四則演算を処理できる。一方、モデル向けの既存プロンプト生成器は据え置いた。次の比較では、新しい許可関数・実数主値・数値と記号証明の違いを両条件へ同じように伝える指示を、正確なプロトコルとして承認する必要がある。実装済みというだけで、その指示や新しい実行器が承認されたとは扱わない。

## 問いと対照条件

主案は「一般的な計算道具に加えて qni-cli があると何が変わるか」を測る。

| 条件 | 共通の道具                                                                | qni-cli                                              |
| ---- | ------------------------------------------------------------------------- | ---------------------------------------------------- |
| なし | 私有作業場所の読み書き、制限した Python 標準ライブラリと NumPy による計算 | 利用不可。実行、読み込み、外部サービスへの迂回も禁止 |
| あり | 同じ道具・同じ上限                                                        | 回路作成・調査・検算用のコマンドを追加               |

「すべての道具なし」と「qni-cli だけあり」の比較も選べるが、その差は反復や計算道具一般の効果を含む。qni-cli 固有の上乗せ効果とは分けて解釈する。この選択は人間がプロトコル承認時に決める。両案を勝手に同時実行しない。

課題本文、ゲート一覧、出力契約、共通の説明は両条件で同じにする。片方だけに文法のコツや正解の例を加えない。道具定義と利用可否に必要な差分は、実験上の操作として保存する。出力文法の改善と道具利用の改善を混同しないため、不合格は回路の不一致、形式・文法違反、採点器エラー、実行エラーに分けて報告する。

## 対象と順序の案

対象は以前と同じ4モデルである。

- `openai-codex/gpt-6-luna`
- `openai-codex/gpt-6.1-sol`
- `claude-bridge/claude-sonnet-5-5`
- `claude-bridge/claude-opus-5-5`

初回は各モデル1つの思考量に限り、共通で利用可能な `high` を候補にする。まだ決定していない。別の思考量を選ぶ場合も、同じモデル内の対では固定する。思考量の全組合せは今回の初回案には含めない。

63課題は以前の `c8ed36f52b2ad3d27cc9477696d64d1d333f0594` を使う案とする。同じモデル・課題・反復について、両条件を独立した新しいセッションで実行する。片方の回答、道具出力、採点、履歴をもう片方へ渡さない。条件の先後を固定した乱数種で釣り合わせ、全呼び出しを直列にする。可用性や版の途中変更があれば停止する。

試験測定は、`basic-gates/two-qubit-gate-1`、`preparing-states/three-states-two-qubits`、`qft/qft` の3課題を候補とする。4モデル×2条件×3課題で24課題実行になる。ここで道具の権限、利用量、漏えい防止、実行時間を検証し、全63課題の実行を別途承認する。試験測定の回答を全測定に再利用するかも、開始前に決める。

反復1回の全測定は504課題実行となる。まず探索的な観測として報告し、モデルの確率的なばらつきまで推定したとは主張しない。確認実験としては独立した3反復を候補にするが、試験測定の結果を見て回数と予算を改めて承認する。

## 道具ができること・できないこと

道具ありでは、実際に `qni add`、`qni rm`、`qni clear`、`qni gate`、`qni state`、`qni variable`、`qni view`、`qni run`、`qni expect` と、それらのヘルプを実行できるようにする。自分の回路と自分で用意した入力の検算に使う。初回はテキスト出力に限定し、画像入力の違いを持ち込まない。

`qni benchmark`、`qni research`、隠した採点器、標準解、課題の検証条件、既存のモデル回答、研究記録へのアクセスは禁止する。道具側へそれらのファイルを配置せず、ネットワークやホストの認証情報も渡さない。任意のシェル実行を許して禁止コマンドへ迂回できる設計にはしない。作成・編集・検算できる範囲を、実際の許可コマンドとファイル権限で検証する。

最終提出は同じ中立 JSON とする。採点は両条件とも、道具と分離した非公開の qni 採点器で行ってよい。これは解答中の援助ではない。採点結果を解答中に返さない。

## 上限の候補と課金の記録

1課題の全体で、モデル呼び出し最大6回、道具呼び出し最大12回、モデル出力合計24,000トークン、入力合計96,000トークン、解答の経過時間300秒を候補にする。道具1回は5秒、出力8,000文字を候補とする。これらは条件間で同じにする。入力はキャッシュの読み書きも含む提供元の報告単位で数える。同じトークン上限がモデル間で同じ計算量を意味するとは扱わない。

| 対象            | 課題実行数 | モデル呼び出し上限 | 出力合計上限 | 入力合計上限 | 解答時間の合計上限 |
| --------------- | ---------: | -----------------: | -----------: | -----------: | -----------------: |
| 試験測定、反復1 |         24 |                144 |      576,000 |    2,304,000 |              2時間 |
| 全63課題、反復1 |        504 |              3,024 |   12,096,000 |   48,384,000 |             42時間 |
| 全63課題、反復3 |      1,512 |              9,072 |   36,288,000 |  145,152,000 |            126時間 |

道具とモデルの待ち時間は300秒に含め、非公開の事後採点・保存・照合は別に計測する。前景実行の外側上限は、試験測定では各モデル・条件の3課題に1,050秒、全測定では各63課題に19,800秒を候補にする。8組を通した上限はそれぞれ2時間20分、44時間、3反復では132時間となる。実行環境が上限を受け付けなければ開始せず停止し、黙って背景実行や短い制限へ変えない。

これは最悪時の上限であり、期待実行時間の予測ではない。以前の4モデルの high では、252回答の出力小計が65,827トークンだったが、道具付きの複数回呼び出しの消費量をそれで見積もることはできない。試験測定で全ターンの実績を取り、全測定の見積もりを出す。

全モデル呼び出しの入力・キャッシュ・出力・思考内訳、終了理由、モデル・提供元、時間を保存する。成功した最終ターンだけに限らず、途中のターン、失敗・中断、道具の引数・出力・終了コード・時間も残す。ストリーム更新や終了時の再掲を二重計上しない。思考分を出力へ再加算せず、不明は不明のまま残す。自動圧縮、補助のモデル呼び出し、自動再試行、代替経路は禁止する。

Codex の記録単価は参考推計に使えても実請求額ではない。Bridge の登録料金0から費用を推定しない。料金または購読枠の上限も、人間が承認する必要がある。認証・割当・使用量・応答の同一性の問題や、未説明の採点器エラーが出たら以後の呼び出しを止める。
