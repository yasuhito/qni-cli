# 思考量比較に先立つ実行停止の修正

実施日: 2026-11-04 (UTC)

Quantum Katas の思考量比較を始める前に、`qni research solve` が認証・利用上限エラー後も呼び出しを続ける問題を修正した。実モデル測定はまだ始めていない。元の63課題ベースラインと修正後の診断結果は変更していない。

## 再現と修正

実際の Pi と、429を返すローカルサーバーを使って3課題を実行すると、修正前は両経路とも3要求を送った。Codex は3 error を保存したが、Bridge はエラー説明文を回路回答として扱い、3 disallowed を保存した。

修正では次を変えた。

- 作成直後の空の課題ディレクトリだけを `--approve` で承認し、その中に再試行無効化、SSE、自動要約無効化、キャッシュ保温無効化の設定を置く。`--offline` で実行中のモデルカタログ更新を止める。
- Bridge の呼び出し環境で再試行と代替経路を無効にする。グローバルの Bridge、認証、設定は編集しない。
- 事前確認したプロバイダーを各呼び出しに明示し、応答のプロバイダー・モデルと停止理由を本文の形式検証より先に検査する。
- 最初の Pi 実行エラーで後続の呼び出しを止める。正式な研究試行は作らず、実際に試みた課題だけの部分記録を一時ディレクトリへ残す。不許可の回路回答では残りを続行する。

部分記録の形式と扱いは [モデル別コストベンチマーク利用手順](../model-cost-benchmark.md) に記載した。再開機能や自動再試行は追加していない。

## ローカル検証

外部通信を遮断するため、`unshare --user --map-root-user --net` でホストとは別のネットワーク名前空間を作り、loopback だけを有効にした。認証は外部のダミー専用ディレクトリに置き、実資格情報は渡していない。名前空間内だけの root 起動には `IS_SANDBOX=1` を使った。測定時の実行条件とは区別する。

最初の Codex 事前確認では fetch の差し替えだけでは通信を遮断できず、ダミー認証が外部バックエンドで拒否された。この失敗を受け、以後の要求捕捉と修正検証は OS 側の隔離内だけで実行した。実モデルの回答は得ていない。

| 検証                                                | 観測結果                                                                                |
| --------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 実際の Pi とローカル401/429/503、両経路             | 各1要求で終了コード3。部分記録は1件、正式な研究試行はなし                               |
| 再試行有効・自動 transport のダミー用グローバル設定 | qni が作成する課題設定で上書きされ、再試行と WebSocket 接続はなし                       |
| 空本文のモデル・プロバイダー不一致                  | 本文の空判定より先に不一致を検出し、後続の呼び出しなし                                  |
| 不正 JSONL、aborted、本文付き error                 | 各1呼び出しで停止。エラー理由を保持                                                     |
| 不許可の回路回答                                    | 3課題を続行し、3 disallowed の正式な研究試行を保存                                      |
| 応答しない偽 Pi                                     | 元の5分上限で停止し、後続の呼び出しなし。残存する所有プロセスなし                       |
| 生 JSONL の外部保存                                 | 課題呼び出しごとに1ファイル。終了コードを維持し、時間切れのシグナルを子プロセス群へ転送 |

最初の不許可回答の検証では、空回路を使ったため採点器が failed と error を返し、検証側の想定が失敗した。この記録は保存したまま、形式が明らかに不正な回答を使って検証し直した。課題や採点器は変更していない。

外部証拠は `/tmp/qni-model-effort-matrix-evidence/` に置いた。再現用の `safety-repair-probe.mjs`、`pi-raw-launcher.mjs`、`safety-repair-validation/`、`safety-repair-final-validation/` が対応する。自動回帰テストは `features/cli/research_solve_safety.feature.md` と既存 solve の機能仕様で実行する。全体チェックの出力は同ディレクトリの `repair-npm-check.log` に保存する。自動テストから有料リクエストは送らない。

## 利用量の欠測とエラー応答

安全修正のレビューで、エラー応答やモデル・プロバイダー不一致を検出すると、応答に含まれる正の利用量まで0へ置き換えていた回帰を見つけた。応答を保持する型付きエラーを使い、実際の応答元、停止理由、本文、報告された利用量と料金を部分記録へ残すよう修正した。不一致の応答を解答として受け付けることはない。応答が得られない場合や個別の項目が欠ける場合は `null` とし、既知の他の項目は失わない。

非ゼロ終了前に最終応答が出ていた場合も利用量を保持する。課題呼び出しと準備確認の生の標準エラーは公開せず、末尾各64 KiB以内の非公開診断を残す。外部 SIGTERM を時間切れと誤認する判定も除き、`ETIMEDOUT` と区別した。

回帰テストは `features/cli/research_solve_accounting.feature.md` に追加した。OS 側の隔離内でも15条件を検証し、正の利用量の保持、応答なしの欠測、非ゼロ終了、元の5分上限での時間切れを確認した。証拠は外部の `accounting-repair-validation/` に保存した。元の検証記録は変更していない。

## 測定候補と未実施の作業

OS 側の隔離内で要求を捕捉した結果、重複のない実効設定は次の21条件だった。63課題ずつなら計1,323課題になる。これは候補数であり、測定済みの件数ではない。

| プロバイダー / モデル           | 実効設定                                    |
| ------------------------------- | ------------------------------------------- |
| openai-codex/gpt-6-luna         | none (`off`)、low、medium、high、xhigh、max |
| openai-codex/gpt-6.1-sol        | low、medium、high、xhigh、max               |
| claude-bridge/claude-sonnet-5-5 | low、medium、high、xhigh、max               |
| claude-bridge/claude-opus-5-5   | low、medium、high、xhigh、max               |

Codex Luna の minimal は low と同じ。Sol の off と minimal も実際には low になる。Bridge は両モデルとも off と minimal が low になるため、重複する点は測定しない。Bridge の陽性対照ではプロジェクトの言語・フック設定が要求に現れ、`settingSources: []` では現れなかった。

実行版は Pi / pi-ai 1.5.0、既存報告と同じパッチを当てた pi-claude-bridge 0.9.3、Agent SDK 0.3.293、SDK 同梱 Claude Code 2.1.293。修正の起点は `41585f9cdd058d385fe5bf78c41f956130ae83e1`。main の CI 修正だけを取り込み、課題、プロンプト、回路文法、採点器は変えていない。修正後の正確なコミットは Riddim の安全確認報告に記載する。

出力トークンは思考分を含むプロバイダーの値を使い、思考分を二重加算しない。Codex の Pi は欠けた reasoning を0へ変換するため、0だけでは実際の思考量が0とは判定できない。内訳が取れない値は不明と記載する。Bridge の保存料金0は無料や請求額を意味しない。Claude Code プリセットと OAuth アカウント情報を含む文脈も Codex と異なるので、後続の比較では経路の違いを明記する。実際のメールアドレスは公開しない。

測定、集計表、重ね合わせ折れ線図は、安全修正の確認後に別途実行する。OpenRouter、直接の Anthropic API、代替プロバイダーは使わない。
