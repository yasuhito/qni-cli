## 空の操作列の採点器修正

修正コミットは `e79e9056fae382821de1e70def54e0c2eb4d8ad9`。保存済み Luna/off の `basic-gates/two-qubit-gate-1` と空の提出物を実際の `qni benchmark run` へ渡し、`circuit.json does not exist` と終了コード3を再現してから修正した。

1・2・3量子ビットの正しい恒等変換、誤った空提出、準備した状態の保持、各種の検証、通常の空でない提出、偽モデルを使った `research solve` を実際の CLI で検証した。専用10シナリオが成功した。修正コミットの全体チェックとコミットフックは1,553シナリオ・4,183ステップで成功した。

別に時間切れの呼び出しが2件ある。これらは1,323選択回答とは別の試行であり、利用量が不明なものを0とみなしていない。

逆三角関数で不許可になった76回答は、元のゲート・順序・制御・対象を変えず、角度だけを別提出物で数値化した。Python の AST を限定して読み、数値、`pi`、四則演算、単項符号、1引数の `sqrt` / `asin` / `acos` / `atan` だけを計算した。任意コードの評価はしていない。最初に試した数値ラジアン文字列は既存契約が拒否したため、その診断も残し、最終診断では既存文法の小数係数×`pi` に変換した。係数は小数点以下17桁とした。

同じ修正採点器で元の数値検証条件を実行すると、72件が合格、4件が不合格になった。文法や元回答を直した結果ではなく、角度式を数値近似した別提出物の診断である。全入力に対する記号的な証明でも、元の正式な採点結果の置換でもない。

不合格の4件は Luna/off の `preparing-states/hardy-state`、Luna/medium の `preparing-states/three-states-two-qubits-phases` と `preparing-states/wstate-power-of-two`、継続 Luna/max の `preparing-states/wstate-arbitrary` だった。その他の JSON・引数数違反は修復していない。

次の比較前には、空提出修正を固定したうえで、角度表現の契約を別件として決める必要がある。文法を承認なく拡張してはいない。今回の診断は、文法違反を量子回路の誤りと一括りにすると評価を誤ることを示す有限ケースの証拠である。
