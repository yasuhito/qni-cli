# FourBitstrings: 補助量子ビットの必要性の検証

調査基準: upstream `7c6a2b5116b30169d97567318bd84d50cc6ee19b`、`katas/content/preparing_states/four_bitstrings/{SolutionA,SolutionB}.qs`。Stage PC ではこの課題を一般化せず、既存の固定課題・標準解を変更しない。

## 結論

「任意の異なる四つのビット列の等重ね合わせには補助量子ビットが必須」は誤り。上流 SolutionA は2個使うが、SolutionB は補助量子ビットを全く使わず、接頭辞で制御した Ry を再帰的に適用する。qni-cli の回路実行器は Ry と多重制御 X を扱えるため、追加の量子ビットなしで構成できる。

ただし**現在の固定課題が宣言する許可集合 H/X/Z/CNOT と、CLI 全体が実装するゲート集合は別**である。この固定課題の許可集合だけで任意の四列を準備できる、という意味ではない。後述の反例はその集合では補助量子ビットを追加しても解決できない。「補助量子ビット不足」ではなく「非Clifford操作の不許可」が障害である。

## 補助量子ビットなしの一般構成と証明

長さ N の異なる四列の集合 S を考える。接頭辞 p を持つ列数を m(p)、その次が0の列数を m(p0) とする。m(p)>0 の各接頭辞（長さ k<N）で、先頭 k ビットが p のときだけ q[k] に

`Ry(2 acos(sqrt(m(p0)/m(p))))`

を適用する。空接頭辞では通常の Ry。0制御は前後の X で正制御に変える。未使用の接頭辞は飛ばす。再帰呼び出しは古典的計算であり、追加の量子ビットではない。

深さ k で各接頭辞の振幅が sqrt(m(p)/4)、残りのビットが0という不変条件を保つ。回転の cos と sin はそれぞれ sqrt(m(p0)/m(p))、sqrt(m(p1)/m(p))。よって子の振幅は sqrt(m(pb)/4)。深さ N では四つの葉が全て1/2、その他は0。負の相対位相も生じない。分岐比3:1も扱えるので、二つの識別ビットだけに常に均等分岐できるという仮定は不要。

多重制御 Ry が中立JSONにない場合にも、MCX と通常 Ry で分解可能。角度 θ の制御回転は時系列で `Ry(θ/2); MCX; Ry(-θ/2); MCX`。制御不成立なら回転は相殺し、成立なら X Ry(-θ/2) X = Ry(θ/2) により Ry(θ)。制御線は変更しない。したがって Ry/X/MCX で足りる。単制御 Ry は既存CLIでも直接扱える。

## 固定課題の許可集合に対する反例

N=3、S={000,001,010,100}。Clifford回路がゼロ状態から作る純粋な安定化状態の計算基底上の台はアフィン部分空間である。この四点はアフィン平面でない（四点の XOR が111で0でない）。したがって等振幅状態は安定化状態でなく、H/X/Z/CNOT では作れない。ゼロ初期化した補助量子ビットを加えてもClifford回路は安定化状態を保ち、補助を切り離して純粋な目標状態を得ることはできない。

既存の固定値 S={001,011,100,110} はアフィン平面で、H/X/CNOT の既存標準解が通る。これを一般四列へ拡張するには許可ゲート契約の変更が必要だが、補助量子ビット必須という理由で拒否してはならない。今回は指定どおり固定値のまま保留する。

## 実行確認

`/workspace/katas-work/pc-four-verify.cjs` で N=3 の異なる四列の全70集合を列挙し、上記接頭辞回転を Ry/X/MCX に分解した補助なし回路を fresh build の Simulator で確認した。全70件で目標四振幅が+1/2、残り0、虚部0（誤差1e-9以内）。非アフィン反例 {000,001,010,100} も含む。`pc-four-verify.log/.exit` は PASS 70/70、exit0。これはローカルのみの未コミット調査用スクリプト・実行記録であり、リポジトリ読者がこの絶対パスを利用できるとは限らない。再構成する手順は上の角度式・再帰とMCX分解に示した。FourBitstrings課題の一般化実装はリポジトリに追加していない。
