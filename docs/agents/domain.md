# Domain Docs

Matt 系エンジニアリングスキルが、このリポジトリのドメイン文書を読むときの規約を示す。

## 読むべき文書

作業前に、必要に応じて次を読む。

- ルートの `CONTEXT.md`
- `docs/adr/` 以下の ADR

このリポジトリは **single-context** として扱う。`CONTEXT-MAP.md` は使わない。

これらのファイルが存在しない場合は、問題として扱わず、そのまま作業を続ける。`/domain-modeling` は、用語や決定が固まった時点で必要なファイルを遅延作成する。

## ファイル構造

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
│       ├── 0001-example.md
│       └── 0002-example.md
└── src/
```

## `CONTEXT.md` の役割

`CONTEXT.md` はドメイン用語集として扱う。実装計画、作業ログ、仕様詳細、課題分割は置かない。

出力でドメイン概念を名付けるときは、`CONTEXT.md` にある用語を優先する。明示的に避けるべき別名が書かれている場合は、その別名を使わない。

必要な概念が `CONTEXT.md` に無い場合は、すぐに実装名を増やすのではなく、まず用語として定義すべきかを検討する。

## ADR の役割

`docs/adr/` は、将来の読者が「なぜそうしたのか」を疑問に思うような、戻しにくい設計判断を記録する場所とする。

既存 ADR と矛盾する提案をする場合は、暗黙に上書きせず、矛盾を明示する。
