# 可変長・離散引数課題は上限付きJSON生成器を複数入力で採点する

## 判断

Stage PC は ADR 0029 の approach a を実装する。可変 N、配列、離散整数・真偽値の課題では、一つの中立JSON回路生成器を各採点ケースの入力で展開し、具体的回路を数値検証する。**有限個の検証であり、全 N・全入力の正しさの証明ではない。** 固定幅・連続引数のPA/PB記号証明を置き換えず、証明失敗の救済にも使わない。

呼び出し側は既存の `gradeBenchmarkTask` / `gradeBenchmarkSuite` を使う。課題の `parameterized` 宣言は、入力定義域、ケース、指定幅、参照、位相方針を所有する。他の採点宣言との併記は禁止。提出は `neutral-parameterized-circuit-json-v1`、宣言が課題と完全一致する必要がある。各ケースで新しい環境と空の回路を生成し、ケースをまたぐ状態は持たない。

状態準備は指定幅のゼロ状態から全体位相まで比較する。幅の追加も失敗にし、旧run採点のゼロ補完の幅違反見逃しを継承しない。ユニタリ課題は ADR 0028 の全基底入力比較を再利用する。共通の行列全体位相のみ許容し、列ごとの補正はしない。RotationGate は上流のStrict契約を維持する。

## 構造と代替案

`parameterized_circuit.ts` が文法、宣言、資源予算、ゲート権限と具体的回路生成を隠す。`parameterized_grading.ts` が参照との比較とケースの集約を所有する。JSON構文木を評価ランナーのコマンド層へ露出させない。利用例は `qni benchmark run task.md answer.json --json`、一括実行では全課題の形式から `.json` を選ぶ。

別案として子プロセスで旧中立操作列へ展開し `.qni` に変換する構造を比較した。旧変換の角度契約は π 式文字列で、可変長W状態の数値逆三角関数や指定幅を自然に保持できず、余分な変換・一時ファイル・コマンド再解釈が必要になるため不採用。任意コード実行はそもそも不要。上限のあるデータ言語を直接解釈する構造を採用し、別案の長所である通常ファイルの上限付き読込、全分岐の構文検査、独立したケース環境を取り入れる。

## 隔離と制限

これは任意JavaScriptの実行環境ではない。式文字列、eval、関数呼出し、再帰、while、ホストオブジェクト、測定、ファイル・ネットワークAPIを提供しない。Mapによる変数環境と固定演算だけを解釈する。同一記述子を `O_NONBLOCK` で開き、通常ファイル確認後、実際の読込も64 KiB+1で打ち切る。FIFO・デバイスを待たない。

提出64 KiB、構文深さ16・節点2048、配列256、ケース2〜32、幅1〜8、操作1024、ケース当たり式評価・文実行・ループ反復の合計100000、有限数の絶対値1000000。空ループでも反復を数える。検証済み構文と数値の上限により、解釈器は有限のCPU・メモリ内で動く。OSで任意コードを隔離する仕組みではなく、ホストAPIに到達できないデータ言語の境界である。シミュレーターの費用も幅・操作数で制限する。採点ケースと参照は信頼する評価者が用意する。

不正提出・上限・幅・権限・数値不一致は failed/exit1。課題不備・欠落した提出ファイルは error/exit3。構文検査は未実行の分岐にも行う。実行時の添字・型・定義域は各ケースの評価時に検証する。未評価のselect分岐の数式まで全域定義を証明する言語ではない。

## 非公開入力と履歴

各課題に公開例以外の入力と N=1 などの境界を含める。`hidden` は評価者向けの分類で、結果はケースIDと判定だけを出し入力値を含めない。ただし**リポジトリに同梱するケースはソースを読めば分かり、暗号学的に秘密ではない**。本番では評価者が公開課題本文と提出宣言を変えずに私有の課題ファイルへ未公開ケース・期待値を追加する。提出物はケースID、参照、hiddenの値を参照できず、宣言した入力だけを見る。有限ケースへの過適合を排除する全域証明とは呼ばない。

旧数値63件、記号6件は保持。可変入力12件を別スイートに追加し、合計81課題ファイル（一般化版の重複を含む）。AllBellStates は旧4ファイルに対応する新1課題。UnequalSuperposition は上流でも単一量子ビットなので一般Nを捏造しない。QFT RotationGate の整数 k を12件目に含める。

FourBitstrings は固定値のまま。上流SolutionBの接頭辞制御Ry構成は補助量子ビット不要。ただし現固定課題のH/X/Z/CNOTだけでは非アフィンな四列の等重ね合わせは作れず、補助の追加でも解決しない。必要なのは非Cliffordゲート契約の拡張であって補助必須ではない。調査の詳細を [検証記録](../research/finding-four-bitstrings.md) に残す。

ADR 0002/0022/0027 の旧コマンド・JSON変換・角度契約を暗黙拡張しない。研究記録は `research record --submissions` で独立プロトコルとして保存し、混在を拒否する。旧JSON変換と `research solve` は明示拒否する。ADR 0019 に従い過去結果を再採点・移行しない。
