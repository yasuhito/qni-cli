# ADR 0023: モデル筆記試験を隔離した Pi 経由で実行する

## 状況

`qni research solve` は、qni-cli が `research/models.yaml` を読み、OpenAI互換 Chat Completions API を直接呼ぶ実装だった。この方法ではモデル接続、認証、思考量、料金表を qni-cli が個別に管理する必要がある。一方、普段のモデル利用では Pi がこれらを管理しており、同じ設定が二重化していた。

Pi を共同研究者として道具付きで実行すると、採点条件や標準解を読める可能性があり、既存の `blind-neutral-circuit-json-v1` による公平比較とは別の評価になる。直接 API と道具付き Pi を同じ `solve` に混ぜる案もあるが、結果の意味と実験条件が曖昧になる。

## 決定

`qni research solve` は道具なしのモデル筆記試験として維持し、モデル呼び出しをインストール済み `pi` コマンドへ一本化する。

- 課題ごとに空の一時作業場所で新しい Pi プロセスを起動する。
- Pi の道具、セッション、文脈ファイル、スキル、拡張機能、プロンプトテンプレートを無効にする。
- qni-cli が短い system prompt と中立化した課題文を渡し、厳格な中立回路 JSON の最終回答だけを採点・保存する。
- モデル ID と思考量は CLI で必須指定する。
- モデル登録、認証、利用量、料金は Pi を情報源とし、`research/models.yaml` と OpenAI互換 API の直接呼び出しを廃止する。
- 道具を使い、試行錯誤や自己修正を行う共同研究者評価は `research solve` に混ぜず、将来別の機能として設計する。

## 結果

qni-cli は量子回路課題、提出プロトコル、採点、研究試行保存に集中できる。Pi に登録したモデルと認証を再利用でき、`--thinking max` などの実験条件も明示できる。

実行環境には互換性のある `pi` コマンドが必要になる。再現性のため、研究試行には Pi の版、モデル ID、思考量、選択課題、Pi が報告した利用量と料金を保存する。Pi 自体の変更による結果差は完全には排除せず、保存した版から追跡する。
