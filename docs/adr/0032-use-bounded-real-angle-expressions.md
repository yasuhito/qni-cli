# 数値経路の角度式を限定した実数構文木で扱う

保存済みの76回答は `asin`、`acos`、`atan` と引数内の `sqrt` を必要とし、π の数値係数への手作業の置換では、元の解答をそのまま検証できなかった。人間の承認に基づき、既存 `AngleExpression` の数値 API に四則演算、括弧、単項符号とこの4関数を追加する。文字列の部分置換や任意コードの評価ではなく、限定した構文木を読み、実数主値をラジアンで計算する。依存ライブラリや複素数の体系は追加しない。

数値は既存と同じ IEEE 754 の `Number` であり、式を保存しても評価結果を厳密値とは呼ばない。`sqrt` の引数は非負、`asin` / `acos` は評価した引数が閉区間 [-1,1]、`atan` は有限実数とする。中間値の非有限値、0除算、定義域外を拒否し、丸め誤差を理由に範囲外を暗黙に切り詰めない。数値の丸めはあり、実数全体の記号的な定義域証明ではない。

入力と正規化後の文字列は4,096文字、構文木は256節点、括弧・関数・単項演算および木の深さは64を上限にする。未知の関数、属性参照、配列、任意 JavaScript を実行しない。宣言した角度変数の既存 API と、π・`pi`・数値付きの `pi_N` 別名、既存の基本表記は維持する。変数をグローバルやプロトタイプから解決しない。旧表記用の正規表現は表示互換にだけ使い、構文・評価の判断には使わない。

[ADR 0027](0027-extend-neutral-gates-with-separate-mcx.md) の具体的な π 式だけという制約を、中立 JSON に限って「π または逆三角関数を構文木に含む具体的な実数式」へ拡張する。裸の数値ラジアン、変数、純粋な数値計算だけの角度は引き続き許可しない。ゲートの引数数や `available_gates` は緩めず、[ADR 0022](0022-separate-neutral-json-and-legacy-qni-protocols.md) の変換境界と提出プロトコル識別子を維持する。現在のモデル向けプロンプト生成器と過去の保存プロンプトは変更しない。今後の実験に渡す指示は、両条件をそろえた正確なプロトコルとして別途承認する。

[ADR 0029](0029-use-symbolic-proof-for-fixed-width-parameter-tasks.md) の記号証明は独立した経路のままである。厳密な表示用補助プログラムが数値 API の新しい式に対応しない場合、明示した記号実行は未対応と伝える。通常の `run --latex` は既存の方針で丸めた数値表示へ戻せるが、記号的な正しさの証明に使わない。

旧行列、回答、採点結果、図は移行しない。人間が承認したオフライン診断は、元の回答から、新しいソース HEAD・式文法の版・出典ハッシュを持つ別の診断として生成する。新しいモデル回答や道具利用の効果とは扱わない。
