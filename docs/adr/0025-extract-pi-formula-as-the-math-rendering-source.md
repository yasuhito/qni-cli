# ADR 0025: 数式描画の正本を pi-formula へ分離する

## 状況

qni-cli に同梱した数式描画拡張は、Pi の会話本文にあるインライン数式を Unicode テキストで、表示数式を MathJax 画像で描ける。実装は Pi の公開 API だけを使い、Ghostty と Kitty の実端末で確認済みである。

一方、数式描画の大部分は量子回路 CLI に依存しない。qni-cli の中に置き続けると、量子計算を使わない Pi 利用者が単独で導入できず、数式描画と qni 専用ツールの責務も同じ入口に混在する。独立版と qni-cli 版へコードを複製すると、修正と試験が二重になり、どちらが正しいか分からなくなる。

## 決定

数式描画を、独立した汎用 Pi 拡張 `pi-formula` として分離する。数式描画コードの正本は `pi-formula` リポジトリだけに置く。

- pi-formula は量子計算を前提にせず、分野固有のマクロを標準では持たない。
- インライン数式は Pi 標準の Unicode テキストで、表示数式は画像対応端末では MathJax 画像で描く。
- qni-cli は pi-formula の公開インターフェースを使い、量子系マクロと qni 専用ツールだけを追加する。
- qni-cli は確認済みの pi-formula の版を同梱し、`pi install npm:qni-cli` 一回で従来の体験を提供する。
- pi-formula 単体と qni-cli を両方導入しても、数式描画と `/formula` コマンドは一つだけ登録し、qni-cli の量子系マクロを追加する。
- pi-formula 0.1.0 を qni-cli 0.1.0 より先に公開する。

## 結果

量子計算を使わない Pi 利用者も、`pi install npm:pi-formula` で数式描画だけを導入できる。qni-cli は数式描画の実装を持たず、量子回路と計算結果の責務へ集中できる。

独立パッケージの公開、版管理、Linux と macOS の検証、二重導入の調整が新たに必要になる。pi-formula の変更を qni-cli へ取り込むときは、依存版を明示的に上げ、qni-cli 側でも実端末確認を行う。

## 検討した選択肢

- qni-cli の中だけに残す: 一回の導入は簡単だが、汎用機能を量子計算へ閉じ込め、責務の混在を残すため採らない。
- pi-formula と qni-cli にコードを複製する: 個別に変更できるが、修正、試験、仕様が分岐するため採らない。
- qni-cli 利用者にも pi-formula を別途導入してもらう: パッケージ境界は単純だが、Qni CoResearcher の一回の導入体験を壊すため採らない。
