# 数式描画 PRD

> GitHub issue: https://github.com/yasuhito/qni-cli/issues/381（`ready-for-agent`）。grilling（2026-08-28）、[ADR 0024](../adr/0024-render-chat-math-images-through-public-pi-api-only.md)、調査メモ [pi-math-and-pi-rendering-api.md](../research/pi-math-and-pi-rendering-api.md)（節 E・F）、[headless-terminal-visual-check.md](../research/headless-terminal-visual-check.md)、プロトタイプ（`prototype/qni-math` ブランチの `ANSWERS.md`）を材料にまとめた仕様。用語は `CONTEXT.md` の「数式描画」節に従う。

## Problem Statement

研究者が Pi の中で共同研究者と量子回路を設計・検証するとき、状態ベクトルや演算子は LaTeX で書かれる。しかし端末では `\frac{1}{\sqrt{2}}(\ket{00}+\ket{11})` のような原文か、Pi 内蔵の Unicode 整形（`\ket` は非対応で原文のまま、分数は不格好）でしか読めない。qni-cli が計算した状態ベクトルも `sqrt(2)/2|00> + sqrt(2)/2|11>` という ASCII で、論文の記法とかけ離れている。研究者は数式を頭の中で組み直しながら会話を読むことになり、共同研究の速度と正確さが落ちる。

先行実装の pi-math は Pi の本文中の LaTeX を画像として描けるが、別途インストールが要り、`\ket` などの量子系マクロは利用者が設定しないと使えず、Pi の非公開の内部を書き換える方式に依存し、qni-cli の結果には関与しない。

## Solution

qni-cli パッケージに **数式描画拡張**（識別子 `qni-math`、コマンド `/math`）を同梱し、`pi install qni-cli` だけで数式描画が使えるようにする。

- **画像経路**: Pi の本文に書かれた表示数式を MathJax で組版し、Kitty グラフィックスプロトコルの画像として端末に描く。Ghostty と Kitty で論文と同じ見た目になる。Pi の公開 API だけを使う（ADR 0024）。
- **テキスト経路**: インライン数式は、`\ket` などの量子系マクロを Pi 内蔵の Unicode 整形が理解できる形に前処理して描く。画像が使えない端末では表示数式にも使う。
- **量子系マクロ**は設定なしで最初から使える。
- **qni-cli のツール結果も数式にする**: `qni run --latex` と `qni expect --latex` が `\ket{}` 記法の LaTeX を出力し、拡張が登録する専用 `qni` ツールの結果ブロックに画像として描く。スキルは共同研究者に、状態ベクトルを LaTeX で本文に引用するよう指示する。
- 端末の画像対応は環境変数ではなく、実際に使う形式（PNG）で端末に問い合わせて判定する。判定は `/math` で手動で上書きでき、既定はセッションと全体設定に記憶できる。
- 実装の検証は、AI エージェント自身がヘッドレスの実端末でスクリーンショットを撮って目視する手順を含める。

## User Stories

1. 研究者として、共同研究者が本文に書いた `$\ket{\psi}=\frac{1}{\sqrt2}(\ket{00}+\ket{11})$` を本文と同じ大きさの Unicode テキストで読みたい。行間を乱さずに会話を追えるようにするためだ。
2. 研究者として、`$$...$$` や `\[...\]` で囲んだ表示数式を本文とは別の行に中央寄せ相当で読みたい。長い式や分数を落ち着いて確認するためだ。
3. 研究者として、`\ket`、`\bra`、`\braket`、`\otimes` を何も設定せずに使いたい。量子計算の論文と同じ記法をそのまま書けるようにするためだ。
4. 研究者として、`\(...\)` や `\[...\]` でも `$` でも同じように描画されてほしい。共同研究者や自分の書き癖に依存しないためだ。
5. 研究者として、共同研究者が返答を書いている途中でも、閉じたインライン数式は Unicode テキストで、表示数式は画像で読みたい。返答の完成を待たずに内容を追うためだ。
6. 研究者として、返答が完成したあとの画面に古い描画や `Working...` の残像が残らないでほしい。会話の記録を信頼して読み返すためだ。
7. 研究者として、端末のテーマが暗くても明るくても数式が読めてほしい。文字色は本文と同じで、背景は透明であってほしい。
8. 研究者として、文中のインライン数式は本文の行の高さに収まっていてほしい。行間が乱れて段落が読みにくくならないためだ。
9. 研究者として、qni-cli が計算した状態ベクトルを、共同研究者の解釈を挟まずにそのまま数式として読みたい。計算結果と説明を区別して検証するためだ。
10. 研究者として、`qni run --latex` の出力が `\ket{00}` 記法で書かれていてほしい。本文の数式やスキルの指示と同じ方言で読み、コピーして使えるためだ。
11. 研究者として、SymPy を準備していない環境でも数値の状態ベクトルを LaTeX で読みたい。Python の準備なしでも数式描画の価値を得るためだ。
12. 研究者として、`qni expect --latex` で期待値を `\langle ZZ \rangle = 1.0` の形で読みたい。観測量の記法を論文と揃えるためだ。
13. 研究者として、`qni run --symbolic --latex` で記号的な状態ベクトルを LaTeX で読みたい。`alpha`、`beta` のような記号を含む式を正確に読むためだ。
14. 研究者として、共同研究者が `qni` ツールで実行した結果のブロックに、状態ベクトルの画像が出てほしい。共同研究者の説明を待たずに計算結果を確認するためだ。
15. 研究者として、ツール結果のブロックを折りたたんでも展開しても画像が枠に収まっていてほしい。会話の流れを崩さないためだ。
16. 研究者として、共同研究者が本文で状態ベクトルを引用するとき、qni-cli の LaTeX 出力をそのまま `$$...$$` で引用してほしい。書き換えによる誤りを避けるためだ。
17. 研究者として、qni-cli をインストールするだけで数式描画が使えてほしい。別の拡張を探して入れる手間をなくすためだ。
18. 研究者として、Ghostty と Kitty では表示数式と qni-cli の LaTeX 出力が画像で描かれることを保証してほしい。自分の主な作業環境で最良の見た目を得るためだ。
19. 研究者として、tmux や VS Code 内ターミナルなど画像が使えない端末でも数式を Unicode で読みたい。環境によって会話が読めなくならないためだ。
20. 研究者として、端末が「画像対応」と答えるのに実際には描けない環境（herdr など）でも、自動で正しくテキスト経路に落ちてほしい。見えない画像を送られて空白だけが残らないためだ。
21. 研究者として、`/math status` で今の経路（画像かテキストか）、判定の根拠、直近の失敗理由を確認したい。数式が期待どおりに出ないときに原因を突き止めるためだ。
22. 研究者として、`/math image` と `/math text` で経路を手動で切り替えたい。自動判定が外れたときに自分で直すためだ。
23. 研究者として、手動の切り替えがそのセッションに記憶され、再開しても保たれてほしい。同じセッションで何度も打ち直さないためだ。
24. 研究者として、`/math text --default` のように既定を全体設定に保存したい。自動判定が常に外れる環境で毎回打たずに済むためだ。
25. 研究者として、`/math auto` で自動判定に戻したい。環境が変わったときに手動設定が残り続けないためだ。
26. 研究者として、`/math clear` でキャッシュを捨てたい。表示が壊れたときに最初からやり直すためだ。
27. 研究者として、量子系マクロ以外の自分専用のマクロを追加したい。研究分野固有の記法を使うためだ。
28. 研究者として、不正な LaTeX が本文にあっても拡張が落ちず、その数式だけ原文か Unicode で表示されてほしい。1 つの誤字で会話全体の表示が壊れないためだ。
29. 研究者として、thinking ブロックの中の LaTeX は描画対象外でよい。thinking の表示色を崩さないためだ。
30. 共同研究者（量子回路AIエージェント）として、`qni` ツールに引数の配列を渡して qni-cli を実行したい。シェルの引用符やパイプ記号の解釈に悩まず、`state set "alpha|0> + beta|1>"` のような引数を正確に渡すためだ。
31. 共同研究者として、`qni` ツールの説明から `["--help"]` で使い方を確認できると知りたい。巨大な引数スキーマを毎ターン読まずに済むためだ。
32. 共同研究者として、`qni` ツールの結果を文字列としても受け取りたい。画像が読めなくても計算結果を推論に使うためだ。
33. 共同研究者として、スキルから「状態ベクトルは `--latex` で取得し `$$` で引用する」という指示を受けたい。研究者に正確な数式を見せるためだ。
34. 共同研究者として、`bash` から `qni` を呼んだ場合も従来どおり動いてほしい。古い手順やスキルが壊れないためだ。
35. Qni CoResearcher の保守者として、数式描画拡張が Pi の公開 API だけを使っていてほしい。Pi の版更新で予期せず壊れないためだ。
36. 保守者として、Pi の版更新で画像経路が使えなくなったとき、拡張がテキスト経路に落ちて `/math status` に理由を出してほしい。利用者の会話が読めなくならず、原因を追えるためだ。
37. 保守者として、拡張のコードが qni-cli の他の部分から独立した境界に置かれていてほしい。将来別パッケージに切り出せるためだ。
38. 保守者として、数式描画拡張の振る舞いが Cucumber の日本語シナリオとして読めてほしい。仕様と実装の対応を確認するためだ。
39. 保守者として、`npm run check` に組版の重い処理や実端末の起動を入れたくない。全体チェックを速く保つためだ。
40. 保守者として、実端末での見た目を AI エージェント自身が確認できる手順と脚本がほしい。人間の目視を待たずに反復し、完了の判定を確かなものにするためだ。
41. 保守者として、`npm run smoke:package` で同梱した拡張が tarball に入り、Pi から読み込めることを確認したい。公開前に配布物を検証するためだ。
42. 保守者として、pi-math のコードを本実装に残さず、設計メモから独自に書いてほしい。独自実装と言い切り、帰属表示に依存しないためだ。
43. 保守者として、MathJax は非推奨の `mathjax-full` ではなく後継の `@mathjax/src` を使ってほしい。インストール時の警告と将来の保守負担を避けるためだ。

## Implementation Decisions

### 全体構成

- 数式描画拡張は qni-cli の npm パッケージに同梱し、`package.json` の Pi manifest で拡張として宣言する。利用者の追加インストールは不要。
- 拡張のコードは `src` 配下の独立したディレクトリに置き、qni-cli の他のモジュールを import しない。逆方向（CLI が拡張を import する）もしない。後で別パッケージに切り出せる境界を保つ。
- CommonJS は維持する（ADR 0001）。Pi は拡張を jiti で読み込むため、拡張のビルド成果物が CommonJS でも問題ない。MathJax v4（`@mathjax/src`）は CommonJS の配布物を持つ。
- Pi が同梱するコア（`@earendil-works/pi-coding-agent`、`@earendil-works/pi-tui` など）は `peerDependencies` に `*` で宣言し、同梱しない。MathJax と Resvg は `dependencies` に置く。
- 拡張は Pi の公開 API（`registerMarkdownTransformer`、`registerTool`、`registerCommand`、`appendEntry`、テーマ取得、UI ファクトリ引数の TUI）だけを使い、pi-tui や Pi 本体の内部関数やプロトタイプを書き換えない（ADR 0024）。

### 本文の数式描画

- 数式の検出は `$...$`、`$$...$$`、`\(...\)`、`\[...\]` の 4 種。コードフェンスとインラインコードの中は対象外。thinking ブロックは対象外。
- `$...$` と `\(...\)` は画像へ変換せず、量子系マクロと利用者マクロを展開して Pi の Unicode テキスト経路へ残す。本文と同じ大きさ、濃さ、ベースラインになり、コピー、検索、折り返しも保たれる。
- `$$...$$` と `\[...\]` は MathJax v4 で TeX → SVG、Resvg で SVG → 透明 PNG に組版する。文字色は Pi のテーマから取得した本文色、背景は透明。自然な高さで、幅が利用可能幅を超えるときだけ縮める。
- 表示数式の配置は Kitty の Unicode プレースホルダー方式。プロトタイプで確認した成立条件を守る。
  - PNG の転送と仮想配置は同じ `a=T,f=100,q=2,U=1` 命令で指定し、**メッセージ先頭の 1 行**にすべてまとめる。数式ごとに別行にすると再描画で「転送行数 − 1」行ぶんずれ、末尾に置くと悪化する。
  - Kitty の仕様に従い、プレースホルダーの前景色（`38;2;r;g;b`）に画像 ID、下線色（`58;2;r;g;b`）に配置 ID を符号化する。配置後は `39;59m` で両方を戻す。
  - プレースホルダー（U+10EEEE と行・列の結合文字）は Ghostty / Kitty ともに 1 セルで、pi-tui の幅計算と一致する。
- 以下はプロトタイプが確定した形（決定を正確に伝えるための抜粋）。

  ```text
  転送行:      ESC _G a=T,f=100,q=2,U=1,i=<画像ID>,p=<配置ID>,c=<cols>,r=<rows>[,m=1] ; <base64> ESC \
  配置セル:    ESC [38;2;<画像ID> m ESC [58;2;<配置ID> m  (U+10EEEE + 行の結合文字 + 列の結合文字) × cols  ESC [39;59 m
  ```

- ストリーミング中も変換器は動き、閉じた数式（区切りが完結したもの）だけを画像化する。未完成の数式は原文のまま残す。
- 画像 ID は数式・表示種別・色・利用可能幅・行数の組に対して安定させ、再描画で同じ ID を再利用する。SVG と PNG は上限付きのキャッシュに置き、失敗も記録して再試行を避ける。
- 変換器は同期・軽量でなければならない。組版の初回は同期で行い、以後はキャッシュを返す。

### テキスト経路

- 画像が使えないとき、変換器は量子系マクロ（`\ket`、`\bra`、`\braket`、`\otimes` など）を Pi 内蔵の Unicode 整形が理解する素の LaTeX に展開した Markdown を返し、描画は Pi に任せる。
- 目標は「必ず読める」こと。美しさは画像経路の責務とする。

### 端末判定と経路の選択

- Pi 自身の判定（環境変数だけを見る）は信用しない。拡張は起動時に、実際に使う形式（PNG、`f=100`）の Kitty 問い合わせ（`a=q`）を端末に送り、タイムアウト付きで応答を待つ。`OK` が返れば画像経路、`EINVAL` や無応答ならテキスト経路。herdr のように「問い合わせに `OK` を返すが PNG を拒む」中間層も、この方式で正しく判定できる（実測済み）。
- 応答は UI ファクトリ引数の TUI（`terminal.write` と入力リスナー）で読む。tmux / screen 下では Pi が画像を止めるので問い合わせをせずテキスト経路。
- 判定結果で pi-tui の公開 `setCapabilities` を上書きし、Pi 全体の画像判定も正す。
- 経路は `auto`（既定）、`image`、`text` の 3 値。`/math image|text|auto` はそのセッションに記憶（`appendEntry`）し、`--default` を付けると拡張専用の設定ファイル（利用者のホーム配下）に全体既定として保存する。優先順位はセッションの指定 > 全体既定 > 自動判定。
- `/math status` は経路、判定の根拠（問い合わせの応答、環境変数、手動指定）、キャッシュの件数とバイト数、直近の組版失敗を表示する。`/math clear` はキャッシュを捨てる。

### 量子系マクロと利用者マクロ

- `\ket{}`、`\bra{}`、`\braket{A|B}`、`\otimes` などを組版時に既定で定義する。`physics` パッケージ相当の最小集合から始め、必要に応じて増やす。
- 利用者は環境変数または拡張の設定ファイルで JSON のマクロ定義を追加できる。

### qni-cli の LaTeX 出力

- `qni run --latex` は状態ベクトルを LaTeX で 1 行出力する。通常は数値実行と同じ入力検証を行ったうえで、SymPy の記号実行が扱える回路では規模によらず厳密な振幅を優先する。記号実行は巨大な密行列を作らず、状態ベクトルへゲートを直接適用する。記号実行環境が利用できない場合または回路が未対応の場合は、TypeScript で組み立てた数値表示へ戻る。明示的な `--symbolic --latex` の対象範囲と出力書式は変えない。
- どちらも `\ket{}` 記法に正規化する。SymPy の `\left|...\right\rangle` は `\ket{...}` に書き換える。数値フォールバックは Python を使わず、浮動小数点誤差を抑えるため実部と虚部を15桁の有効数字へ丸める。
- `qni expect --latex` は 1 行に 1 観測量を `\langle ZZ \rangle = 1.0` の形で出力する。
- `--latex` は測定を含む回路の `--shots`/`--json` とは併用できない（既存の制約に合わせる）。
- 既存の出力契約（フラグなしの出力）は変えない。

### 専用 `qni` ツール

- 拡張は `qni` という名前のツールを Pi に登録する。引数は文字列の配列 1 つ（例: `{"args": ["run", "--symbolic", "--latex"]}`）。シェルを介さず同梱の qni-cli を子プロセスで実行し、作業ディレクトリはセッションの作業ディレクトリ。
- ツールの説明文に「`["--help"]` で使い方を確認できる」と書き、引数スキーマは配列だけに留める。
- ツール結果の本文（モデルに渡す文字列）は qni-cli の標準出力そのまま。結果の詳細（表示専用）に LaTeX を持たせ、結果描画では公開の `Image` 部品で画像を返す。画像が使えないときは文字列を表示する。
- 組み込み `bash` は上書きしない。`bash` 経由の qni は従来どおり文字表示。

### スキルの更新

- 同梱スキルは、qni の実行に `qni` ツールを優先し、状態ベクトルや期待値を説明するときは `--latex` の出力を `$$...$$` で本文に引用するよう指示する。数式は `$` 系の区切りと `\ket` 記法で書くよう指示する。

### 検証の脚本

- ヘッドレス実端末（`xvfb-run` + Ghostty / Kitty）で Pi を再開し、スクリーンショットを撮る脚本を `scripts` に置く。数式入りのセッションファイルとストリーミング用の固定応答プロバイダを固定資産として持ち、暗・明テーマ、静止・ストリーミング、ツール結果の折りたたみ・展開を撮る。
- この脚本は `npm run check` に含めない。実装完了の判定条件として、担当エージェントが撮って読み、結果を PR に添える。

## Testing Decisions

- よいテストは外から見える振る舞いだけを比べる。検出・組版・キャッシュ・端末判定・Kitty 符号化などの内部モジュールをテストから直接触らない。
- 継ぎ目は 2 つ（自動）+ 1 つ（目視）。
  1. **qni CLI のプロセス境界**（既存）: Cucumber が `qni run --latex`、`qni run --symbolic --latex`、`qni expect --latex` を実行し、標準出力を比べる。先行例は `qni run --symbolic` の feature。1 シナリオに `Then` は 1 つ。機能追加の前に feature ファイルを書く。
  2. **Pi 拡張の入口**（新規）: 拡張の登録関数に偽の ExtensionAPI を渡し、登録された Markdown 変換器・`qni` ツール・`/math` コマンドを直接呼ぶ。Cucumber のシナリオは「`$\ket{0}$` を含む本文を変換すると、マクロを展開した Markdown が返る」「`$$\ket{0}$$` を含む本文を画像経路で変換すると、先頭 1 行の転送と画像配置のプレースホルダーが返る」「画像不可の判定ではマクロを展開した Markdown が返る」「未完成の数式は原文のまま」「`qni` ツールに配列を渡すと qni-cli の標準出力が結果になる」「`/math text` のあとの `/math status` はテキスト経路を示す」のように、利用者と共同研究者から見える振る舞いを書く。必要なら返った Markdown を pi-tui の `Markdown` 部品に Node 上で通し、行の出力まで比べる。組版の細部（SVG の寸法、PNG の大きさ、キャッシュの上限）は `node --test` に置く。
  3. **実端末の目視**: ヘッドレス Ghostty / Kitty のスクリーンショットを AI が読む。`npm run check` の外。
- 端末判定は、偽の端末応答（`OK`、`EINVAL`、無応答）を注入して 2 の継ぎ目で検証する。
- `npm run smoke:package` に、tarball に拡張が含まれ Pi から読み込める確認を足す。

## Out of Scope

- Pi 本体や pi-tui への変更（`58;2` の SGR 解析の修正、Markdown 描画の差し替え hook の提案）。上流への提案は別課題として扱う。
- pi-math との共存や互換（`/math-render` コマンド、`PI_MATH_*` 環境変数）。
- 既存の `qni export --png`（pdflatex 経由）の MathJax への置き換え。
- iTerm2、WezTerm、Warp での画像の保証。これらは互換扱いで、動けば幸い。
- herdr の実験的 Kitty 描画の有効化や、herdr 側の対応。
- Pi 以外のエージェント環境（Claude Code など）での数式描画。
- 密度行列や回路図など、状態ベクトルと期待値以外の qni-cli 出力の LaTeX 化。
- `--shots` の共同分布（測定結果）の LaTeX 化。

## Further Notes

- 決定の経緯は grilling の決定一覧（Q1〜Q17）にあり、要点は ADR 0024 と `CONTEXT.md` の「数式描画」節に記録済み。
- プロトタイプは `prototype/qni-math` ブランチにあり、コードは捨てる前提。本実装は調査メモとこの仕様から書き、プロトタイプのコードを写さない。

- 主利用者の普段の環境（herdr）は画像を描かないため、日常的にはテキスト経路が見える。画像経路の確認はヘッドレス Ghostty / Kitty の脚本で行う。
